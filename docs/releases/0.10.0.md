This release is the command line's third, and the one that makes `scmjs` a tool for
teams and for bot authors. A map's triggers can be tested in the game from a tests file,
two versions of a map can be merged, git included, bots can play a ladder against each
other on one computer, and a melee map can be made from a seed. The command line guide
was rewritten by task and has pictures.

## Testing a map's triggers

- `scmjs map test ridge.scx` runs the scenarios in `ridge.tests.json` in the game itself:
  units placed, switches set and orders given at the frames you name, then what the
  scenario expects at the end: a trigger fired, a switch set, a death count, units in a
  location, a text shown, a victory. Every failed scenario leaves a replay beside the
  map, so you watch what went wrong.
- `--format github`, `junit` and `sarif` put the results where CI reads them. A test run
  needs a copy of StarCraft, so the workflow `scmjs init` writes names the command in a
  comment rather than a step.

## Merging two versions of a map

- `scmjs map merge base.scx ours.scx theirs.scx` merges two versions of a map part by
  part: terrain tile by tile, units and doodads as sets, locations by slot, triggers as an
  ordered list, settings field by field, strings following whatever refers to them.
  What only one side changed is taken; what both changed differently is a conflict, listed
  and settled with `--ours` or `--theirs`.
- `scmjs init` now sets the command up as git's merge driver for `.scm`, `.scx` and
  `.chk`, so `git merge` merges maps on its own and stops on a real conflict as it does
  for code.

## A ladder for bots

- `scmjs bot ladder a.scmbot b.scmbot computer --maps *.scx` plays every pairing on every
  map, both seats, as many games as you ask, and prints the standing: Elo, games, won,
  lost, undecided, length and the time each bot takes a frame. Every game's replay is
  saved.
- Two bots play each other on one computer with no server: the runner keeps two copies of
  the game in step, so the same seed gives the same game however long a bot thinks.

## A map from a seed

- `scmjs map generate ridge.scx --players 4 --tileset jungle --seed 7` lays out a
  symmetric melee map: a high-ground main with one ramp for each player, a natural below
  it, free bases, an open middle with obstacles, minerals and gas placed as the Melee
  Wizard places them. It walks every start to every other before writing, and prints the
  resources and distances per player. The same seed gives the same map. It needs a copy
  of the game for the tileset.

## Smaller additions

- `scmjs map triggers edit` and `scmjs map strings edit` open the text in your editor
  and import it when you close it. Nothing changed, nothing written; a parse error keeps
  the file and tells you how to import it again.
- `--qr` on `map share`, `replay share`, `map play` and `account` prints the link's QR
  code under the link, for a phone across the table.
- `scmjs map sounds ridge.scx` lists the sounds in a map, and `map sounds export` writes
  them out as `.wav` and `.ogg` files you can play.

## Documentation

- The command line guide on docs.scmjs.dev is organised by what you are doing: getting
  started, looking inside a map, making and changing one, maps in git, running a map in
  the game, replays, sharing, bots, developers, and a command reference. Eleven pictures
  show what the commands print. Old addresses forward.

## Fixes

- The repository's ignore rules now match a symlink at a game-data path as well as a
  folder, after a merge brought such links into the tree. If you pulled `main` on
  2026-11-07 and your `fixtures`, `node_modules`, `plugins` or `public` data folders turned
  into dangling links, delete the links and run `npm ci`, `npm run extract` and
  `npm run vendor:plugins`.
