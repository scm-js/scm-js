Saving a map no longer makes it larger, a file that is not a map is no longer opened as
one, and the `scmjs` command line was gone over from end to end: every command run against
real maps, replays, mods and a bot, and what that found put right. Some of what changed is
behaviour a script may rely on; **What a script will notice** below lists it.

## Saving and opening

- Saving a map that StarEdit made with sounds in it no longer grows the file. Its sounds
  were written back uncompressed, which made such a map about 2.7 times larger on any
  save, even a rename: a 573 KB map became 1.5 MB. Sounds that did not change are now
  written as they were stored, in the editor's Save and in every `scmjs` command that
  writes a map.
- A file named `.scm`, `.scx` or `.chk` that holds no map is refused. It used to open as
  an empty 64 × 64 map, and a command that wrote to it replaced the file.

## The command line: work that could be lost

- `scmjs map triggers import` refuses a file with no triggers in it, which used to remove
  every trigger of the map. `--allow-empty` says it is meant.
- `scmjs mod unpack` into a folder that already holds an unpacked mod is refused unless
  `--force`. It used to write over the folder, and what had been changed there was gone.
- `map triggers edit` and `map strings edit` keep your text when the map cannot be
  written, and say the command that brings it in.
- `map unpack` no longer mixes two maps in one folder: a folder of another map, or one
  whose files changed since it was unpacked, is refused unless `--force`.
- The tools `scmjs mcp` gives an AI refuse an argument they do not know. A misspelt
  `dryRun` used to be dropped, and the map was written.

## The command line: what was broken

- Stopping a command stops the game it started. A game kept running at full speed after
  the command was killed, cancelled by CI or cut short by a pipe; temporary folders were
  left behind too.
- `map test record` takes `--json`, `--frames` and `--starcraft`; it ignored all three.
- A misspelt key in a tests file is refused, with the nearest key it knows. Such a test
  used to pass, or check the opposite of what was meant.
- `map rush` on a map with units placed on it reports the walks of the unit asked for;
  it listed hundreds that were not.
- `map diff --rev A..B` is refused, where it reported the whole map as added;
  `--rev main...` compares with where the branch left main. `map log` lists commits in
  git's order.
- A replay saved from a game of a mod by `bot ladder`, `map test --mod` or `mod test`
  says which mod it was.
- `bot run` reads its values and its files before the game starts; `--frames abc` ran no
  game and reported success.
- `map pack --out -` and `mod pack -o -` write to standard output; they wrote a file
  named `-`.
- `scmjs doctor` starts the browser it finds, and says when it does not start.
- A missing file, a folder where a file is wanted and the like are said in one line; about
  ten of them printed an internal error.
- Shell completion offers options after a file name, the values an option takes, and the
  commands it lacked. Write the script again: `scmjs completion bash`.

## The command line: one way of doing things

- `-o` is `--out` on every command that writes, and `-` is standard output wherever one
  file is written.
- `--force` means writing over what is there, and nothing else. Taking replays of another
  map in `map heatmap` and `map coverage` is `--any-map`; packing a mod despite errors in
  `mod build` is `--ignore-errors`.
- `--all` means the whole list. The whole-map camera of `replay export` is `--whole-map`.
- `--size` is a map's size. A clip's size in `replay export` is `--resolution`, and the
  picture's size in `replay watch` is `--cells`.
- `--frames` takes a number of frames or a time such as `1:40`, and a race is its name or
  its first letter, in every command.
- With `--json`, standard output is the JSON and nothing else, and a file is named as it
  was typed.
- What a command says while it works goes to standard error, so `> report.txt` holds the
  report alone.

The old spellings of the renamed options still work.

## New on the command line

- `scmjs map --help` and `scmjs mod --help` list their commands by what they are for.
- `--dry-run` on `map set`, `map resize`, `map pack` and both imports; `--json` on both
  imports and both edits.
- `map dump` lists sprites, doodads and the settings that differ from a new map's, and
  gives each section a hash, so painted terrain shows in `git diff`.
- `mod new --tables units,weapons` starts a mod from the game's own tables as text.
- `map resize` lists what it drops, and names a start location among them.
- `scmjs help map diff` works, and a mistake in a command line names the help that lists
  that command's options.
- A release now reaches Homebrew and Scoop when it is published; they used to find it
  hours later.

## What a script will notice

- A mistake in the command line, a missing file and a file of the wrong kind exit with 2.
  Some of these exited with 1.
- `map dump` has a new form, so every map shows once in a `git diff` set up by
  `scmjs init`. If git keeps showing the old form, clear what it kept:
  `git update-ref -d refs/notes/textconv/scmjs`.
- `map optimize --keep` is given once for each member: `--keep a --keep b`.
- `mod diff a b` exits with 1 when the two mods differ, as `map diff` does.
- `map trace … | head` no longer ends the game early: its progress is on standard error.
- `-v` after a command is an unknown option. Before, it printed the version and the
  command did not run.
- `scmjs mcp` reads and writes only inside the folder it was started in.
  `--allow-outside` lifts that.
- A folder `map unpack` wrote with an earlier version may ask for `--force` once.
