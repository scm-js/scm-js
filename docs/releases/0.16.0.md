The command line and an AI tool can now paint terrain, place doodads and change the
Scenario menu's settings. Your scmjs.dev account is reachable from the terminal: links at
a moment of a replay, the library, and your games' replays stored as they are saved. On a
map linked to the editor, the tools work with the editor's own game data.

## Terrain, doodads and settings

- `scmjs map edit` paints terrain by type with the editor's isometric brush, so a cliff
  forms where the height changes and a shore beside water. An edit paints an area or the
  ellipse inside it, a share of the area in patches placed by a seed, and the same stroke
  mirrored or turned about the map.
- It places and removes doodads too. A doodad is refused where StarEdit would refuse it;
  asked for `ramp` near a tile, the edit finds a ramp that fits the cliff there. A
  category can be scattered over an area.
- A placed unit can be put on the building grid, and a position the editor would refuse
  can be refused: unbuildable ground, another unit in the way.
- `scmjs map terrain` lists the tileset's terrains and draws the map as a grid of letters.
  `scmjs map doodads` lists the doodads on the map and the ones the tileset has.
- `scmjs map settings` lists the players, the forces, and the unit, upgrade and technology
  settings a map changes. `scmjs map set --settings` sets them, with the switches' names.
  Every name is checked before anything is set, and each setting that changed is listed
  with its value before and after.
- Terrain, doodads, and a unit's, upgrade's or technology's numbers are read from your own
  copy of StarCraft. The edits and settings that need none ask for none.

## AI tools

- An AI tool set up with `scmjs mcp` can now be asked for a plateau with a ramp, a few
  lakes, or a Protoss computer in the second force. `map_edit` paints terrain and places
  doodads, `map_terrain` and `map_doodads` show the model the ground, `map_settings` and
  `map_set` read and set the settings, and `map_generate` writes a whole melee map from a
  seed.
- The account is there as tools: `account_info`, `library_list`, `library_get`, `share`
  and `replay_sync`, with `library_set`, `library_unlink` and `library_remove`. A tool
  that publishes, uploads or deletes says first what it would do, and does it only when
  called again with your agreement.
- A script run with `map_run` has the game's data when a copy of StarCraft is on the
  computer, so the terrain and doodad parts of the plugin API work there.
- There are 54 tools, up from 42.

## A map linked to the editor

- On a linked map, terrain, doodads and a unit's numbers are laid with the tileset and
  tables the editor has. A mod's ground is painted with the mod's tileset, and the
  command line needs no copy of StarCraft of its own for a linked map.
- The editor hands over the game's tables for this and nothing else: no pictures of
  units, no sounds. The link still runs on your computer only.

## Your account from the terminal

- `scmjs share` takes maps and replays together and gives each its link. `--copy` puts
  the link on the clipboard, and `--no-link` keeps a file on your account without one.
- `scmjs replay share game.rep --at 6:42` makes a link that opens at that moment of the
  game. `--play` sends whoever opens it to the play page, to play on from there as one of
  the replay's players.
- `scmjs library` lists what your account keeps, each link with how often it was opened.
  `library get` downloads a map or a replay, and `library rm`, `unlink` and `rename`
  change what is kept. Deleting says first what goes and asks.
- A scmjs.dev link works where a command takes a file:
  `scmjs replay info https://scmjs.dev/replay/…` reads the replay behind the link.
- `scmjs replay sync` stores the replays of your games on your account, and with
  `--watch` each game as soon as StarCraft saves it. The first run leaves the replays
  already there where they are.
- `scmjs login --device` signs in by a code you allow on any device with a browser, for a
  terminal over SSH or in a container. In such a terminal `scmjs login` picks it by
  itself.

## What a script will notice

- `scmjs map run` gives a plugin the game's data when it finds a copy of StarCraft.
  `--no-game` runs without, as on a build server.
- `map edit --json` and `map run --json` say which copy of the game was used, as `game`.
  `map set --json` lists changed settings as `settings`.
- A list of unit, location, sprite and fog edits writes what it wrote before, and looks
  for no copy of the game.
- A command given a link writes nothing back to it: one that would write over its input
  asks for a file with `-o`.

## For plugin authors

- A plugin run with `scmjs map run` finds `api.tileset.load()` and `api.data.load()`
  answering true where a copy of StarCraft is installed, and the terrain types, the
  isometric brush, doodads and the placement check working as in the editor.
- The API version stays 1.
