This release is the command line's: `scmjs` grew from a reader of maps into a tool for
maps in git, maps in the game, and maps in the hands of AI tools. The editor itself is the
same as in 0.8.11, apart from one change for the play page.

## Command line

- **Maps as text.** `scmjs map dump` prints the whole map as text, and three lines in a
  repository make `git diff` and `git log -p` show what changed in a map instead of
  "binary files differ". `scmjs map triggers export|import` and
  `map strings export|import` take a map's triggers and strings out as files beside it and
  put them back.
- **Comparing and checking.** `scmjs map diff a.scx b.scx` says what changed between two
  maps in a map maker's terms, or since a git revision with `--rev HEAD~1`. `map check`
  gained `--format github`, `junit` and `sarif`, so a workflow puts Check Map's findings
  on the pull request itself. `map info --table` is one row per map for a folder of them.
- **Editing from the terminal.** `scmjs map new` writes a new map with its start locations
  laid out; `map set` is Map Properties; `map resize` is Scenario ▸ Resize;
  `map strings prune` drops the strings nothing refers to; `map find` is Edit ▸ Find
  across any number of maps.
- **Pipes.** `-` as a map's path reads it from standard input, and `--out -` writes it to
  standard output, so the commands chain: `scmjs map new - | scmjs map set - --name Ridge
  | scmjs map check -`.
- **The archive.** `scmjs map unpack` takes a map apart into a folder of its files, and
  `map pack` puts it back together as it was.
- **TrigScript and plugins.** `scmjs map build` applies a map's TrigScript script and
  builds its programs, as Save does, so a map in git can be built where it is checked.
  `scmjs map run` runs a plugin, or a few lines written like one, over a map with the
  plugin API and no editor.
- **The game.** `scmjs map trace` runs a map's triggers in the game itself with nobody
  playing and reports which fired, how often, which never did and what said no.
  `scmjs map cost` weighs them as StarCraft: Remastered charges for them, in milliseconds
  a frame, and names the costliest. `scmjs replay watch` plays a replay in the terminal,
  the minimap redrawn as it goes with every unit in its player's colour, the players'
  figures and the chat under it. `scmjs bot run` plays a bot of your own against the
  game's computers with no page open. These use the play page's engine, fetched once, and
  your own copy of StarCraft.
- **Pictures.** `scmjs map preview` draws a map with the game's own tileset graphics, read
  from your copy of the game: in the terminal, in colour, or as a PNG with `--out`.
- **Replays.** `scmjs replay map` writes out the map a replay was played on; a replay
  carries it whole.
- `scmjs doctor` says what this computer has for each command, which commands are ready,
  and the one thing each other one lacks.
- A shell completion script for bash, zsh or fish: `scmjs completion bash`.

## For AI tools

- `scmjs mcp` runs the map commands as an MCP server on your computer, so Claude Code,
  Cursor, VS Code and other tools that speak the Model Context Protocol can read, check,
  search, compare and change your maps with the editor's own code. Triggers travel as the
  trigger window's text, which the model edits and imports back; `map_preview` answers
  with the map's picture; `map_trace` and `map_cost` run it in the game. With Claude Code,
  once, in your maps folder: `claude mcp add scmjs -- npx -y @scm-js/cli mcp`. The guide
  is at [docs.scmjs.dev/cli](https://docs.scmjs.dev/cli/).

## Replays

- The play page's **Analyse in the Editor**, in its end-of-game menu, hands the game's
  replay to the editor at scmjs.dev, which opens it in Aftermath.

## For plugin authors

- `scmjs map run` is the editor's own plugin host without the editor, so a plugin's logic
  can be tried from a terminal, or run over many maps from a shell loop, before anyone
  installs it.
- `@scm-js/core` gained what the command line needed: the tileset and units.dat decoders,
  the archive read and written as it is, the TrigScript build steps, and a few more
  readers of a scenario.
